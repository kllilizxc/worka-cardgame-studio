This is Worka's preview entry point. Worka conversations and connected Todo items register, start, stop and read diagnostics through this note's public actions and queries. Do not switch to a separate knowledge-base `preview-desk` skill; the knowledge base supplies only shared project startup configuration. A note configured with `previewDesk` shares registration and running services with that preview desk's home. Note state is only a display projection and task association; editing state cannot replace registration. Without the shared service, Worka's host manages the note.

The current agent completes initial integration or startup repairs: investigate → fix the business source and shared recipe → pin the source and rerun the same recipe in a clean runtime directory → actually open the declared entry point → deliver. Put identity and target-permission checks that can run before installation into the existing `check`. Do not copy node_modules, build artifacts or manual patches from the investigation directory for the rerun. Tools, package download caches and explicitly referenced local authorization configuration may be reused. If manual steps are still needed, fix the source before delivery; do not deliver a temporary success.

Formal registration retains the original candidate key. Use an isolated verification directory for the clean rerun; with a shared preview service, a temporary home may be used according to its Skill. Stop the temporary service after verification without changing the original note binding. Ordinary starts and stops still reuse healthy services and preparation results. Read the actual entry point to confirm identity, mounting and primary content. Record source and shared recipe versions, observations and verification limits in the original task conclusion. Do not create another approval, acceptance task or state machine.

`receive` registers a candidate with a stable key, `adapter` (a v3 `preview.config.mjs` in the project or configured knowledge base) and `repos` (role → repository and full commit). For one repository, `cwd + revision` can replace repos, but adapter is still required. Historical `argv + url` or old modules are only for starting, stopping and migrating existing records, not new candidates. Registration declares source; it does not prove the preview is running. `start`/`stop` change desired state and the host converges on it. State is in `status[surface]` for that key in the `candidates` collection; the UI and callers use it as authority.

Every playtest candidate in CardGame Studio is delivered by a connected 「制作待办」 (Todo) item so playtest feedback and `OK` approval route back to its owning session. Pass `originNoteId` (the 「制作待办」 `noteId`) and `delegationId` (the Todo `itemId`): the first candidate uses `key=delegationId` and additional candidates use `delegationId#2`, `#3`, and so on. Updates and retries reuse the key; later synchronization does not erase recorded provenance. Do not register standalone unowned candidates (`receive` rejects candidates without `originNoteId` and `delegationId`).

Connected notes can page through public `catalog({cursor?,limit?})` to discover stable identities, full commits and preview entry points of unarchived candidates. Once selected, call `candidate({key})` for current full state. The catalog returns no runtime logs, credentials or adapter options and does not start previews.

The runner records failure facts and logs; it does not wake another agent for an initial preparation or check failure. The registering agent reads and resolves them directly. The expanded-note composer resolves the current record owner for an ordinary message. Agents use session.list({record:{noteId,recordId}}) to find that session.

An ordinary `start` rereads current scripts and configuration, reuses valid services and checks the entry point. Use the same entry after editing scripts. `stop` stops the whole candidate; individual page entry points are not started or stopped separately. Docker containers persist across host restarts and are released only on explicit stop or archive. A service can be previewed as soon as ready; business checks do not block the page. archive/restore manage archives, forget deletes an archived candidate and its workspace, and rename changes only the title. Startup configuration must rebuild from pinned source commits and must not depend on an unrecoverable local image cache.

For a ready surface, the user can select “Copy LAN address” in the page. The separate preview desk generates the business preview link and copies it through the host clipboard; no agent instruction is needed. LAN sharing requires the configured shared `previewDesk` service and does not expose Worka management interfaces.

When creating or changing preview configuration and helper startup scripts, use the user-specified location and shared project entry. Keep identity, local paths and runtime data local. Configuration examples are in `templates/preview-project`; types are in `@realiz3r/worka-runtime/preview`.


## Card game studio

Register playable CardGame builds through `receive` using this desktop's `playtest/preview.config.mjs` as `adapter` and `repos: {game: {repo: <bound CardGame root>, commit: <full 40-char SHA>}}` (both paths are provided in session context by `game-project`), with `start: true` and `embed: true`. Every candidate must belong to a 「制作待办」 work item: pass `originNoteId` (the Todo `noteId`), `delegationId` (the Todo `itemId`), and `key: <itemId>` (if no Todo item exists yet for this session, create and bind one in 「制作待办」 via `addTodo` + `linkSession` + `recordProgress` first; `receive` rejects unowned candidates), plus `options: {entry: {kind: "story" | "map" | "encounter", resourceId, nodeId?}}` (`resourceId` from `public/data/content-catalog.json`, `nodeId` for a story scene) so the preview opens directly at the affected scene or fight, and post `/notes/<previewNoteId>/candidates/<key>` in the work item's conversation. User reactions while playing route to that linked work item's session; replying `OK` merges the branch into `main` (and pushes when `origin` is a GitHub remote) and marks the work item `done`.
